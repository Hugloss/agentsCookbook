Repository model

Actors and hard authority: who may edit, read, delegate, or execute.

skills/

Standalone methodologies. Manually triggerable and reusable in other flows.

flows/

Composition and ordering only. No duplicate reviewer intelligence.

protocols/

Bounded evidence packets, context budgets, and optional run-local external memory.

Full planning flow

MASTER v1→gap review→alternative route→synthesis→validation→coverage→red team→simulation→fact audit→contract→FINAL

Standalone means standalone

  • A user can invoke one reviewer directly.
  • subagent-router can route one focused configured reviewer.
  • Ping-Pong/Ping-Ping can compose the exact eight mandatory reviewers.
  • Specialist skills can be loaded directly by compatible agents and reused by future flows.
  • Installable specialist skills do not silently become additional mandatory gates.

Low-context design

current subject
+ compact verified facts
+ relevant evidence
+ reviewer-specific task
-------------------------
= bounded review packet

The workflow does not carry whole sibling reports forward. Optional run artifacts can preserve full Markdown reports plus compact receipts outside active context; synthesis reads receipts first and full reports only when needed.

Runtime boundary

OpenCode

Canonical sources are linked into OpenCode's runtime discovery paths. Effective tool permissions are checked after loading.

Pi

The same canonical sources are exposed through Pi + pi-open-agents. Preflight checks links, allowed agents, and shadowing.

Runtime directories are adapters. They are not the repository architecture.
